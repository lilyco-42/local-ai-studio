# ADR-0002：可选算力中心 lain42.top —— 客户端只保存开关与一条命令

日期：2026-10-22 · 状态：已采纳；客户端边界已实现，**尚无一条真连证据**
（本轮只验证"配置能存、命令能显示、默认不发任何流量"）

## 背景

产品要回答一个更远的问题：个人电脑闲置的算力能不能变成可出售的资源。
中心服务器 `lain42.top` 是这条路径的可选入口：用户把自己的机器挂上去，
按贡献换积分，再由服务端结算。这个方向成立的前提不是"功能多"，而是**边界清楚**：
一个本地 AI 工具不该在用户不知情时把机器交出去，也不该把支付逻辑塞进桌面客户端。

## 决策

1. **默认关闭，零出站**：`hub.json` 不存在或 `enabled=false` 时，外壳不解析域名、
   不建立连接、不监听端口。打开开关也只是把配置写回磁盘。
2. **客户端只做两件事**：保存 `enabled / ssh_user / ssh_key`，并显示一条
   `ssh -i <key> -o IdentitiesOnly=yes <user>@lain42.top` 让用户自己复制到终端。
   外壳**不执行**这条命令，也不读取私钥内容。
3. **主机名锁死**：只接受 `lain42.top` 或其子域；带协议、端口、路径、`user@`、或形如
   `lain42.top.evil.com` / `evil-lain42.top` 的一律拒绝。私钥路径只允许 `~/` 或 `/` 开头，
   拒绝 `..`、控制字符与 shell 元字符 —— 因为这条字符串会出现在给人复制的命令里。
4. **节点身份是稳定随机数**：第一次保存时生成 32 位小写十六进制 `node_id`，之后不再变化。
   它不是设备指纹，不含硬件序列号；换机器就是新节点。
5. **积分与支付在服务端**：客户端不登录、不持有凭证、不发起支付、不展示余额。
   用户与服务端之间的信任关系由 SSH 公钥与网页/服务端流程建立。
6. **加速探测与算力出售分开**：`hardware.rs` 的 CPU/GPU/NPU 探测只读本机信息
   （`nvidia-smi`、`vulkaninfo`、`lspci`、PowerShell CIM、`/proc`、`/sys`），
   只用于展示"这台机器适合哪种后端"，不上传。出售算力必须是用户显式开启的另一件事。

## 后果

- 小白路径不受影响：不打开 `lain42.top` 也能完整使用四项本地能力。
- 想接入的用户需要自己保管私钥、自己执行 SSH；客户端不会替他们完成，
  所以"SSH 命令能不能用"属于用户与服务端之间的运维问题，不是外壳的静默行为。
- 负面后果：没有内建的一键接入与余额查询，接入体验比"登录式"产品笨。
  这是有意的：在服务端协议、身份与结算规则稳定之前，不把不可逆的支付/凭证逻辑
  固化进客户端。未来若要做，必须先有服务端协议与独立 ADR。
- 目前没有真连证据：`hub` 的 6 条单测只证明配置校验、默认关闭与命令转义。
  第一次真连必须由用户在真机上用真公钥完成，不能写成 CI 的假证明。

## 不在本 ADR 范围

- 服务端的积分规则、结算方式、提现合规、滥用与内容责任。
- 自动发现局域网节点、NAT 穿透、入站端口、后台常驻代理。
  这些都与"默认零出站"冲突，需要单独决策。
