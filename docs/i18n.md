# i18n：两条轴，别混成一件事

日期 2026-10-19 · 权重与字典的大小来自 `oar-ocr` 的 `docs/models.md` 表格与 release 产物 API 实测；
`digest` 字段同样逐条存在（见 ADR-0001 的更正），所以这些语言包可以按 sha256 钉。

这个产品里"i18n"其实是两件独立的事，成本和做法完全不同：

| 轴 | 内容 | 加一种语言要什么 | 体量 |
|---|---|---|---|
| **A. 识别能力** | OCR 能不能认出这种文字 | 换一个 `*_rec.onnx` + 配套 `*_dict.txt`，**不改代码** | rec 7.4–12.8 MiB，dict 1.9–75 KB |
| **B. 界面语言** | 菜单/提示/错误文案 | 翻译资源 + 复数/语序规则 | 与模型无关，纯前端 |

把两件事写进同一个开关是这类产品最常见的坑：用户以为"我选了泰语界面就能读泰语图片"，
实际上前者是文案、后者是换权重。

## A 轴实测：上游到底给了哪些语言

`docs/models.md` 把识别权重分成两张表：**Chinese/General Models** 与 **Language-Specific Models**。

- **简体中文不是"语言包"，它是通用模型的本职**：`### Chinese/General Models` 下是
  `ch_svtrv2_rec.onnx`(80.3 MiB)、`ch_repsvtr_rec.onnx`(24.2 MiB) 与 PP-OCRv3/v4/v5 的 ch 系列；
  最新的 PP-OCRv6 走的是不带语言前缀的
  `pp-ocrv6_tiny/small/medium_rec.onnx`（**4.3 / 20.2 / 73.0 MiB**），
  配 `ppocrv6_tiny_dict.txt`(6,904 字 / 27,156 B) 与 `ppocrv6_dict.txt`(18,708 字 / 74,947 B)。
  字典里 18,708 个字符这个事实就是"通用包覆盖中日韩"的直接证据，不用猜。
- **Language-Specific 一共 14 种、23 个权重**（每种只取最新版合计 **117.5 MiB**，
  再加共享的 `pp-ocrv5_mobile_det.onnx` 4.6 MiB ≈ **122.1 MiB**）：

"能下的都下"也不到一个 GB，但默认绝不该这么干。）

### 三个必须写进产品的事实

1. **多语言 OCR 便宜到可以不设限**：14 种语言最新版合计 122.1 MiB。
   按实测国内 R2 的 0.82–1.01 MiB/s 约 **2–3 分钟**就能全部下齐。
   这和对话(395.9 MiB 起)、生图(1,494.2 MiB 起)完全不是一个量级，
   所以 OCR 的语言**不该做成"高级功能"**，做成一次可选的多语言包更符合"普通人电脑"这个目标。
2. **繁中、格鲁吉亚语只有 PP-OCRv3 的语言包**，日文也只有 v3 专属包。
   这不是"没支持"，而是**质量上限停在一代之前**：给这些 locale 的承诺不能写成与中英同级，
   要在 UI 里如实标"该语言的专用识别模型较旧"，并允许回落到通用 v6（通用字典 18,708 字符含 CJK）。
3. **权重与字典必须成对下载**：每种语言的 `*_dict.txt` 是独立文件（1.9–75 KB）。
   只下 rec 不下 dict 会静默出乱码，所以目录里每条语言项要同时记两个 sha256，
   下载与校验也按这一对做原子处理。

## 默认集建议（等你拍板）

上游的 det 也是分代的（实测 release 产物）：`pp-ocrv6_tiny_det`(1.69) /
`pp-ocrv6_small_det`(9.42) / `pp-ocrv6_medium_det`(59.15) MiB，另有跨代通用的
`pp-ocrv5_mobile_det`(4.6) 与 v4 系列。所以按"同代成对"给三个候选：

- **极低配（≈6.0 MiB）**：`pp-ocrv6_tiny_det.onnx` 1.69 + `pp-ocrv6_tiny_rec.onnx` 4.3
  + `ppocrv6_tiny_dict.txt` 27,156 B；
- **默认（≈29.7 MiB）**：`pp-ocrv6_small_det.onnx` 9.42 + `pp-ocrv6_small_rec.onnx` 20.2
  + `ppocrv6_dict.txt` 74,947 B（18,708 字符，覆盖简中 + 英 + 常用 CJK）；
- **可省一代体积的混搭（≈24.9 MiB）**：通用 `pp-ocrv5_mobile_det.onnx` 4.6 + v6 small rec 20.2
  + 字典 —— 混代能用（det 与 rec 是独立网络），但要作为**显式选择**记进目录，
  不能默认混用，否则同一份"默认包"在不同版本间漂移时说不清到底装了哪一代。

- **可选包**：其余 13 种语言按需，单个 7.5–12.8 MiB；一键"全部多语言"≈ 122 MiB。
- **界面语言（B 轴）**：建议先 zh-CN / en 双语进 MVP，再按你实际用户补；
  这一轴与 A 轴解耦，加一种界面语言不动任何权重。

### 一个必须写进目录设计的实测陷阱

上游有两个名字只差一个连字符的 det：`pp-ocrv4_mobile_det.onnx`(v0.3.0, 4,826,518 B,
`sha256:ab2a50dc…`) 与 `ppocrv4_mobile_det.onnx`(v0.1.0, 4,782,456 B, `sha256:fd9d4f9b…`)。
**大小与哈希都不同，是两个不同产物。** 所以目录的键必须是 `<版本>/<文件名>` + sha256 三者一起，
只按文件名索引会在老标签里取到另一份权重，而且不会报错——只会识别质量莫名其妙地变差。
